# Gavity 开发计划

状态：产品负责人已确认  
策略：每一阶段形成可运行、可验证的增量，不进行大规模重写。
当前进度：阶段一、阶段二和阶段三已完成本地实现，下一阶段为多人实时与会前体验。

## 阶段一：产品和工程事实来源

交付：

- 产品定义；
- MVP 范围；
- 目标架构；
- 领域规则；
- 固定演示剧本；
- 开发计划；
- 完整 `AGENTS.md`。

验收：

- 文档之间没有角色、权限和 MVP 范围冲突；
- 现有 lint 和 build 继续通过；
- 未修改现有业务行为。

## 阶段二：确定性领域核心

目标：把前端内存逻辑迁移成可在客户端、服务端和测试中复用的纯模块。

交付：

- `shared/domain` 目录；
- 命令、事件和状态 Schema；
- 会议状态机；
- 议事规则模块；
- 授权策略模块初版；
- 现有 UI 适配器；
- 核心单元测试。

验收：

- 主动议、附议、修正、结束讨论和表决有合法/非法测试；
- 现有 Demo 可见行为保持；
- 随机 Bot 不再决定领域规则；
- lint、测试和 build 通过。

## 阶段三：认证、数据库与服务端权威状态

目标：刷新页面后数据不丢失，客户端不再是权威状态。

状态：已完成本地实现与验收。

交付：

- 修正 Better Auth 和 Drizzle 配置；
- 业务数据库 Schema 和 migration；
- 组织、成员、会议、议程、授权、事件 API；
- 服务端命令处理管线；
- 幂等键和事务；
- 集成测试。

验收：

- 客户端伪造用户 ID 无法越权；
- 重复命令不会重复产生动作；
- 会议可以关闭浏览器后恢复；
- 事件历史与当前投影一致。

实现说明：

- 默认首页继续承载隔离的比赛 Demo；
- `?mode=server` 提供阶段三持久化验收控制台；
- D1 使用事件序号和投影版本防止并发覆盖，阶段四再由 Durable Object 提供单场会议的实时单写者；
- 生产部署前需在 Cloudflare Secret 中配置 `BETTER_AUTH_SECRET`，并设置正式 `BETTER_AUTH_URL`。

## 阶段四：多人实时与会前体验

目标：两个或更多客户端能真实参与同一场会议。

交付：

- 创建会议向导；
- 邀请与加入；
- 代理授权编辑器；
- 会前大厅；
- Durable Object 或等价单写者实时协调；
- WebSocket 状态同步和断线补偿；
- 固定演示数据加载器。

验收：

- 两个浏览器状态一致；
- 同时操作不会产生双重发言权或重复投票；
- 服务端控制表决截止时间；
- 演示场景可以从会前大厅开始。

## 阶段五：AI 主持人与数字代表

目标：AI 参与会议，但不能越过确定性规则和授权。

交付：

- 模型调用网关；
- 结构化意图 Schema；
- AI 主持人编排；
- 数字代表编排；
- 上下文最小化；
- Agent 行动解释；
- 提示注入和越权测试。

验收：

- 模型输出不能直接写数据库；
- 非法命令被规则引擎拒绝；
- 代理能说明授权依据；
- 模型不可用时真人仍能完成会议。

## 阶段六：Photon iMessage 真人升级

目标：完成“代理越界—找回真人—恢复会议”的核心差异化闭环。

前置门槛：

- 通过 Photon 官方文档和测试账号确认 iMessage 发送、真人回复接收、回调验证和可用地区；
- 获取比赛期间可用的测试号码、凭据和配额；
- 若任一能力不可用，将其记录为产品阻塞项并交由产品负责人决定，不得自行改成其他主渠道。

交付：

- 真人确认请求；
- 一次性授权；
- 通知重试与过期；
- Photon iMessage 发送与回调适配器；
- 回调验证、幂等和失败状态；
- 站内开发与故障回退。

验收：

- 越权动作在确认前不会生效；
- 确认不能被重复使用或跨议题使用；
- Photon iMessage 能完成真实发送和真人回复闭环；
- 外部消息失败时站内确认可用于恢复，但不能冒充主链路成功；
- 完整演示剧本稳定通过。

## 阶段七：产品收尾与发布

交付：

- 会后决议和时间线；
- 待办生成；
- 错误边界、空状态和移动端基本适配；

- lint、测试、build、migration 检查通过；
- 演示在干净账号和新浏览器中通过。

## Codex 任务模板

每个开发任务都应包含：

```text
Goal:
要实现的单一结果。

Context:
相关文档、文件、现有行为和复现步骤。

Constraints:
必须保留的架构、安全边界和非目标。

Done when:
用户可观察行为、测试、命令和验收条件。
```

推荐一次只交付一个可独立验证的切片，例如：

- “抽离主动议和附议状态转换并补测试”；
- “新增 delegate_mandates Schema 与 migration”；
- “完成越权确认的站内闭环”。

每个任务结束前：

1. 阅读所有修改；
2. 运行相关测试；
3. 运行 lint；
4. 运行 build；
5. 检查 Git diff；
6. 报告已验证内容与剩余风险。
