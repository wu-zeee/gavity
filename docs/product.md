# 在席 Gavity 产品定义

状态：产品负责人已确认  
最后更新：2026-07-24

## 一句话定位

Gavity 是一个由可执行议事规则约束的人类—Agent 协作会议系统：真人无法参会时，可以授权数字代表参与讨论和有限决策；一旦行动超出授权边界，系统必须把决定权交还真人。

## 核心主张

> Agent 可以代表人参与，但不能代表人越权。

## 已确认产品决策

- 仓库和技术名称保留 `Gavity`，对外产品名称为“在席 Gavity”；
- 主赛道为 Photon，其他赛道作为可选叙事，不改变核心产品；
- MVP 首批用户为学生社团和校园组织；
- 数字代表可以在组织规则与个人授权同时允许时条件投票；
- 数字代表是否计入法定人数由组织配置，产品默认不计入，演示组织明确开启；
- AI 主持人负责程序，真人召集人保留暂停、申诉和最终裁定权；
- 真人升级主链路直接接入 Photon iMessage；
- 站内确认仅用于本地开发、自动化测试和外部通信故障恢复；
- “Maker Festival 预算决策会”是固定比赛演示和端到端验收场景。

外部依赖假设：Photon 账号和当前开放能力能够完成 iMessage 发送、真人回复接收与可信回调。进入集成开发前必须用官方文档和测试账号验证；若能力或权限不满足，应立即作为产品阻塞项报告，而不是静默替换主链路。

Gavity 不是普通会议纪要工具，也不是让多个大模型自由聊天的“自动会议室”。它解决的是：当成员不能同时在线时，组织如何继续公平地推进决策，同时保留每个人的知情权、申诉权和最终决定权。

## 首批目标用户

MVP 只服务一个主要场景：

- 有明确成员、议程和表决权的学生社团；
- 需要共同决定预算、活动方案和执行责任；
- 部分成员不能同步在线，但愿意在明确边界内授权数字代表。

产品验证后，可扩展到创作者团队、开源社区、远程团队和公益组织。

## 产品角色

### 真人召集人

- 创建组织与会议；
- 选择议事模板；
- 设置议程、法定人数和表决门槛；
- 处理 Agent 无法裁定的程序申诉；
- 可以暂停或终止会议。

### 真人参会者

- 亲自发言、提出动议、表决；
- 设置或撤销自己的数字代表授权；
- 在关键节点回应升级请求；
- 查看代理行为和决策记录。

### AI 主持人

- 核验会议条件；
- 维护议程、发言顺序和议事状态；
- 将自然语言解释为候选议事动作；
- 解释当前合法的下一步；
- 在规则无法确定时升级给真人召集人。

AI 主持人不得投票、不得代表任何成员利益、不得绕过规则引擎。

### 数字代表

- 依据主人的目标、偏好和授权范围参与；
- 可以观察、发言、附议、提案、协商或条件表决；
- 超出授权边界时停止行动并联系真人；
- 每个动作都必须能解释其授权依据。

### 观察员

- 查看会议和公开记录；
- 不进入法定人数计算；
- 不发言、不提案、不表决。

## 核心用户旅程

1. 用户注册并加入组织。
2. 召集人创建会议、议程和规则。
3. 被邀请者选择真人参会、数字代表参会或不参会。
4. 使用数字代表的成员确认本次会议授权。
5. AI 主持人核验条件并开始会议。
6. 真人与数字代表依规则提出动议、附议、讨论、修正和表决。
7. 代理越界时，系统通过 Photon iMessage 联系真人；本地和故障场景使用站内回退。
8. 真人同意、反对或收窄条件，系统生成有范围和期限的一次性授权。
9. 会议结束后生成决议、待办和可回放审计记录。

## 产品原则

1. **人类主权**：代理权限来自真人，并可随时撤销。
2. **程序公平**：会议状态只能由确定性规则引擎改变。
3. **最小授权**：授权必须限定会议、议题、动作、边界和有效期。
4. **可解释**：所有 Agent 行动必须说明依据。
5. **可审计**：重要动作和授权变化以事件形式保留。
6. **可申诉**：任何参会者都能提出程序异议并请求真人裁定。
7. **安静协作**：系统只在真正越界或高风险时打扰真人。

## 成功指标

MVP 阶段以可验证行为为主：

- 新用户能在 3 分钟内创建一场示例会议；
- 被邀请者能在 1 分钟内完成代理授权；
- 所有非法状态转换都被服务端拒绝；
- 越权代理无法表决，并能触发真人确认；
- 刷新或更换设备后会议状态不丢失；
- 会后能回放每个决策及其授权依据；
- 演示剧本可以在 3 分钟内稳定完成。
