# Gavity MVP 范围

状态：产品负责人已确认  
目标：形成可部署、可多人操作、可稳定演示的完整闭环。

## MVP 必须完成

### 账号与组织

- 邮箱或单一第三方登录；
- 创建一个组织；
- 邀请成员；
- 成员、召集人、观察员三类基础角色；
- 组织级法定人数和表决门槛设置。

### 会议创建

- 创建会议名称、目标和时间；
- 添加、排序议程；
- 邀请组织成员；
- 选择真人参会、代理参会或观察；
- 会前显示法定人数和授权状态。

### 数字代表授权

- 为单次会议创建授权；
- 设置目标、偏好和禁止事项；
- 设置可观察、可发言、可提案、可协商、可表决权限；
- 设置数字/日期等结构化边界；
- 设置必须升级给真人的条件；
- 授权支持撤销和过期。

### 议事流程

第一版只开放：

- 法定人数核验；
- 主动议；
- 附议；
- 发言队列；
- 修正案；
- 结束讨论；
- 简单多数表决；
- 程序异议；
- 对主持裁决的申诉；
- 休会与结束会议。

### AI 主持人

- 宣布当前状态；
- 解释合法下一步；
- 将自然语言转为结构化候选命令；
- 在确定性规则引擎批准后公布结果；
- 无法确定时请求真人召集人处理。

### 数字代表

- 根据授权摘要会议事实；
- 在授权内发言、附议或提出修正案；
- 依据结构化边界决定是否可以继续；
- 越界时创建真人确认请求；
- 获得一次性授权后恢复行动。

### 真人确认

- Photon iMessage 是 MVP 正式环境和比赛演示的主确认渠道；
- 支持向已验证测试号码发送决策摘要和结构化选择；
- 支持接收真人通过 iMessage 返回的同意、反对或修改条件；
- 支持同意、反对、修改条件、查看摘要；
- 确认必须绑定会议、议题、动作和有效期；
- 站内确认页面保留为本地开发、自动化测试和外部通信故障恢复；
- 仅完成站内确认不满足 MVP 正式验收。

### 决策记录

- 记录人类、代理和系统事件；
- 区分提案、附议、修正、表决、裁决和授权变化；
- 会后显示最终决议和投票结果；
- 能按时间回放关键决策；
- 能生成负责人和截止时间明确的待办。

## MVP 完成标准

以下条件必须同时满足：

- 两个浏览器会话能加入同一场会议并实时同步；
- 服务端是会议状态的唯一权威来源；
- 所有写操作通过身份、授权和规则校验；
- 页面刷新后状态和历史完整；
- 演示剧本从创建会议到最终决议可以完整运行；
- Photon iMessage 能完成一次真实的“发送请求—真人回复—恢复代理动作”闭环；
- 自动化测试覆盖核心合法与非法转换；
- `bun run lint`、`bun test` 和 `bun run build` 通过；
- 已部署到独立测试环境；
- 仓库不包含明文密钥或真实用户敏感数据。

## MVP 非目标

第一版明确不做：

- 完整覆盖罗伯特议事规则全部动议；
- 视频会议、音视频转写和会议录制；
- 通用长期人格克隆；
- 多模型自动辩论；
- 同时接入电话、飞书、Slack 等其他渠道；
- 企业级多层审批与复杂组织树；
- DAO、区块链和链上投票；
- 原生移动应用；
- 多语言；
- 计费系统；
- 高并发企业部署。

## 演示模式与真实模式

允许保留演示模式，但必须清晰隔离：

- 演示模式可以加载固定成员、议程和授权；
- 演示代理必须使用确定性脚本或固定种子，不得依赖随机投票；
- 真实模式中的任何代理动作必须经过同样的服务端校验；
- 演示模式不得绕过授权、规则和事件日志。
- 本地开发可模拟 Photon 回调，但正式演示必须使用真实 iMessage 测试链路。
